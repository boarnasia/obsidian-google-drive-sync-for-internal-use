# 同期の設定は Vault 内の `_Sync/` と `_SyncLocal/` に置く

同期から外したいファイルは必ず出てくる。下書き、日記、他人に見せない資料、巨大な添付。これをプラグインの設定画面に持つと、チーム全員が同じ内容を手で入力し続けることになり、一人ずれれば「自分の Vault にだけ現れないファイル」が生まれる。原因は画面のどこにも出ない。

そこで除外規則を Vault 内のファイルに置き、同期そのものに載せて配る。チームで共有する設定は `_Sync/`、各自のものは `_SyncLocal/` に分ける。前者は同期ルート直下にあるので Drive 経由で全員に届き、後者は常に同期の対象外とする。書式は `.gitignore` の部分集合とし、Markdown ファイルとして置く（`#` で始まる行はコメントであり、Markdown の見出しでもある）。

除外は「削除」ではない。すでに同期されているファイルが後から除外規則に載った場合、ローカルもリモートも消さず、以後そのパスを同期の対象外としてベースラインから外すだけにする。共有される設定ファイルに一行足しただけで全員のリモートからファイルが消える、という挙動は、このプラグインが避けている事故そのものである。

clone が残したローカル固有ファイルの行き先も、同じ場所に置く。`_SyncLocal/local-only.md` に「未整理 / 共有 / 削除」の三つのセクションを持ち、未整理にある間はそのファイルのアップロードを止める。分類はサイドバーのボタンでもファイルの直接編集でもでき、保存場所はこのファイル一つだけである。

## Consequences

- `_Sync/` 以下は同期されるため、最初の一人が作った説明文がチーム全員に配られる。内容は英語で固定する。`_SyncLocal/` は配られないので、各自の UI 言語で作る。
- `_Sync/ignore.md` 自身は除外できない。除外を許すと以後ルールが配られなくなり、各自の Vault に古いルールが残って挙動が割れる。`_SyncLocal/` は逆に、常に除外する。
- これらのファイルは clone が成功した直後に、無いときだけ作る。有効化しただけの Vault には何も書かない。clone の前に作ると、自分で作ったファイルが自分のローカル固有ファイルとして未整理に並ぶ。
- `local-only.md` は人とプラグインの両方が書く。プラグインは全文を上書きせず、行の追加と、対象でなくなった行の削除だけを行う。利用者が付けた分類と、セクション外の記述は必ず残す。
- セクションの識別には `<!-- gds:unsorted -->` のような HTML コメントの印を使う。見出しの文言は利用者が自由に書き換えられ、UI が 12 言語あっても壊れない。印を失った見出しは、安全側に倒して未整理として扱う。
