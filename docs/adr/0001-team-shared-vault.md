# チームで一つの共有Vaultを同期する

派生元の obsidian-google-sync は「一人が複数端末で同じVaultを使う」ことを前提に作られている。三方向マージにはロックも編集者の区別も無く、それで足りる設計だった。本製品はこれを「複数人が一つの共有Vaultを使う」用途に転用する。同じファイルを同時に編集することは稀で、担当や時間帯で自然に分かれている、という運用実態を前提として採用した。

この前提が崩れる用途——同じ行を同時に書き換える共同編集——には、ファイル単位の同期では原理的に対応できない。その場合は本製品ではなく CRDT ベースの製品を使うこと。

## Consequences

- 一人の正当な操作が、他の全員の同期を巻き込む。大規模なフォルダ移動が典型で、他人からは大量削除に見える。このため削除の安全装置は「移動を削除と数えない」「上限を超えたら削除だけ保留し、追加と更新は通す」の二段構えにしてある。単一ユーザー前提のままなら、どちらも不要だった。
- 「他人の更新が見えること」が機能要件になる。単一ユーザー用途では同期の遅れは不便でしかないが、共同利用では古い版を見ながら編集を始めることが競合そのものを生む。変更の取り込みを速くする必要がある（ADR-0002）。
- リモートへの書き込みは、利用者が開いているファイルを書き換えうる。Obsidian の Vault API を通して書き、エディタに正しく反映させること。ファイルシステムを直接叩くとエディタと競合する。
