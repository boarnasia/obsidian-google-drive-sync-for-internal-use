# 設定はドットファイルに置き、版の目印で古い版の同期を止める

ADR-0006 では除外規則を `_Sync/ignore.md` という Markdown のノートに置いた。Obsidian で開くと、`#` で始まるコメントは見出しに、規則は本文に化けて表示され、どこが規則なのか読めない。チームで共有するものと各自のもの（`_SyncLocal/`）の二か所に分けたことで、どちらに書くべきかを毎回考えさせてもいた。

そこで割り切る。除外規則は同期ルート直下の `.tds-ignore` 一つにし、`.gitignore` と同じ素のテキストとして扱う。各自用の規則はなくす。ドットで始まるファイルは Obsidian のファイル一覧に出ないので、サイドバーに「開く」と「パスをコピー」を置き、OS のテキストエディタで編集してもらう。

同じ時に、版のずれへの対策を入れる。同期ルート直下の `.tds-version` に、チームで使っている最新のプラグインの版を書く。同期の前にこれを Drive から読む。自分の版の方が新しければ `.tds-version` を自分の版に上げ、古ければ同期を止めてサイドバーで更新を案内する。同期の規則は版ごとに変わりうるので、古い版と新しい版が同じフォルダに書くと、ファイルの二重作成や消したはずのファイルの復活が起きうる。BRAT の自動更新は Obsidian の起動時にしか走らないため、開いたままの人は取り残される。

## Consequences

- `.tds-ignore` は普通のファイルとして同期され、全員に配られる。除外規則に書かれていても除外できない（ADR-0006 と同じ理由）。
- Obsidian の Vault API はドットファイルを索引に載せない。`.tds-ignore` だけはアダプタで読み書きし、一覧にも加える。索引に載らないので変更イベントは来ず、外部エディタでの編集はポーリングの際にローカルの差分として拾われる。
- 規則は Markdown として読まない。箇条書きの記号やコードブロックの柵も、規則の一部として扱う。
- `.tds-version` は同期しない（常に除外する）。Drive を直接読み書きする。Vault に写すと、古い版の手元の写しが新しい版の目印を上書きしうる。
- 版が古い間は sync も clone も止まる。数えるだけの plan() は目印を書かないが、版が古いことはサイドバーに知らせる。
- サイドバーの「BRAT で更新」は、BRAT が有効なときだけ出す。BRAT の `checkForUpdatesAndUpdate` コマンドを実行する。
- 既存の `_Sync/ignore.md` から自動では移さない。移さなかった `_Sync/` と `_SyncLocal/` は、以後は普通のノートとして同期の対象になる。移行する人は、中身を `.tds-ignore` に移してから二つのフォルダを消す。
- `.tds-version` は下げられない。誰かが新しい版を試しただけでも、チーム全員がその版まで上げるまで同期が止まる。戻すには、Drive 上の `.tds-version` を手で書き換える。
