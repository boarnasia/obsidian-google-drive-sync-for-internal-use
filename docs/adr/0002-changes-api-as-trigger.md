# 変更検知に Changes API を使い、差分適用には使わない

共有Vaultでは他人の更新を早く取り込む必要があるが（ADR-0001）、同期の実体であるフォルダツリーの全走査は、フォルダ数だけ順次 API を呼ぶため数十秒かかる。これを短間隔で回すことはできない。そこで Drive の Changes API を「変更があったか否か」を一度の問い合わせで判定する目的にだけ使い、変更があったときにのみ従来どおりの全走査と三方向マージを走らせる。

Changes API が返すのはパスではなくファイル ID である。差分だけを適用する設計にすると、ID からパスへの対応表を永続管理し、親フォルダの移動時に子孫をまとめて更新し、対応表が壊れたことを検出して再構築する必要が生じる。壊れても気づかないまま同期し続ける危険があり、得られる速度に見合わない。

## Consequences

- 同期ルートが共有ドライブ内にある場合、変更ログはそのドライブ固有のものを見なければならない。利用者アカウントの変更ログだけでは取りこぼす。ドライブ種別の判定（ADR-0004）がここでも必要になる。
- ページトークンを永続化する必要がある。トークンを失った場合や、Drive が受け付けなくなった場合は「変更あり」として扱えばよく、正しさは失われない。
- 変更ログはドライブ全体のものなので、同期ルートの外の変更まで「変更あり」と数えると、他の作業で忙しい共有ドライブでは毎回全走査になる。直前の走査で分かったルートの中の ID と、変更されたもの自身・その親の ID を突き合わせて、中の変更だけを数える。外の変更しか無ければトークンを進める。ID の集合は保存せず、起動直後の最初の確認は判断できないものとして同期する。
