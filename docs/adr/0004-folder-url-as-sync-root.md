# 同期ルートはフォルダのURLで指定し、Vault名は使わない

派生元は「アプリフォルダ名 + ローカルのVault名」からリモートのパスを組み立てていた。一人が複数端末で使う限り、Vault名の付与は別Vaultとの衝突を防ぐ正しい設計である。しかし共有Vaultでは、全員が Vault名を一字一句揃えることが暗黙の必須条件になり、揃っていなければ各自が別の場所に同期して、そのことに誰も気づけない。本製品では同期ルートを Google Drive のフォルダ URL で直接指定し、ローカルの Vault名はリモートのパスに一切含めない。

URL を貼る形にすると、共有ドライブのルートも、共有ドライブ内のフォルダも、マイドライブ内のフォルダも、すべて同じ `/drive/folders/<ID>` で表されるため、利用者に種別を選ばせる必要がなくなる。代わりにプラグイン側が ID を引いてフォルダ名と所在を確かめ、画面に表示する。

同様に、ローカル側で指定するフォルダは「同期する範囲の絞り込み」ではなく、同期ルートに対応する**マウントポイント**として扱う。その直下がリモートルートの直下になり、フォルダ名自体はリモートに現れない。各自が自分のVaultの好きな場所を共有Vaultとして繋げる。

## Consequences

- ドライブ種別の表示は必須要件である。共有ドライブのつもりでマイドライブのフォルダを貼ると、本人だけが同期できて他の誰にも届かず、しかも正常に動いているように見える。
- アクセススコープは全 Drive 権限が必要になる。`drive.file` は「そのユーザーに対してこのアプリが作成したファイル」しか見せないため、同じ共有ドライブ上にあっても他人のノートが存在しないものとして扱われる。スコープの選択肢は設けない。
- 同期ルートを変更した場合、ベースラインは破棄して全アップロードから始める。古いベースラインを新しい空の場所に当てると、全ファイルが削除されたと解釈される。
