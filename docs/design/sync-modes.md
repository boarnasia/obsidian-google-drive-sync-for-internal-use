# 同期モードと同期管理サイドバー

ADR-0005 と ADR-0006 で決めたことを、実装できる粒度まで書き下したもの。用語は CONTEXT.md に従う。

## 操作は三つ

| 操作 | 何をするか | 押せる条件 |
|---|---|---|
| **clone**（UI の表示は「Drive から取り込む」） | リモートをローカルに再現する。非破壊 | 接続済みで、同期先が確定している |
| **sync** | 通常の双方向同期 | ベースラインがある。要確認状態ではない |
| **共有 / 削除** | ローカル固有ファイルを 1 件ずつ決める | 未整理のファイルがある |

入れないもの: 強制アップロード（ローカルを正としてリモートを上書き）、転送を伴わないベースライン再構築。前者はチーム全員のデータを一人の判断で壊せる。後者は clone がほぼ同じ処理をする。

## clone（非破壊 Pull）

1. リモートの一覧を取る。
2. 各ファイルについて、
   - ローカルに無い → ダウンロードする。
   - ローカルにあり、内容が同じ（ハッシュ一致） → 何もしない。ベースラインに載せる。
   - ローカルにあり、内容が違う → ローカル版を `{名前}.conflict-<UTC>.md` に退避してから、リモート版を置く。同じ秒に名前が衝突する場合は `-2`, `-3` と連番を足す。
3. ベースラインをこの結果で作り直す。それ以前のベースラインは捨てる。
4. リモートに無いローカルのファイル（退避した `.conflict-*` を含む）は**消さない**。未整理として控え、サイドバーに並べる。
5. `_Sync/` と `_SyncLocal/` が無ければ作る（後述）。

利用者のノートの中身は書き換えない。frontmatter も付けない。ローカル固有であることはサイドバーの一覧で表す。

## 要確認状態

次のいずれかに当てはまると入る。

1. その同期で消すことになるファイル数が、安全上限 `max(10, 追跡数の 20%)` を超えた。
2. ローカルのファイルが 0 件で、ベースラインが空でない。
3. ベースラインが無く、ローカルとリモートの両方にファイルがある。

入っている間の挙動:

- **アップロードを止める**（新規・更新・削除のすべて）。
- **ダウンロードは続ける**。他の人の更新は受け取れる。
- サイドバーに理由と、抜ける道を二つ出す。**clone でやり直す**か、**保留された削除を承認する**か。

条件 2 は 1 に含まれるが、原因を名指しできるので専用の説明文を出す。「Vault が空になっています。Drive 側の N 件を消すか、clone でローカルに再現するかを選んでください。」

## 保留削除の承認

- 対象を一覧表示し、ファイル単位で選ぶ。既定では何も選ばれていない。「すべて選択」を用意する。
- 実行前の確認文: 「選んだ N 件を Drive のゴミ箱に送ります。30 日後に自動で完全削除されます。それ以降も 25 日間は、管理者なら復元できます。」（根拠: Google ドライブのゴミ箱は 30 日で自動削除。管理者による復元は追加で 25 日）
- 実行したものはベースラインから外す。選ばなかったものは保留のまま残る。

## 未整理によるアップロード停止

未整理のファイルは、決まるまでアップロードしない。

- 止めるのは**そのファイル自身**だけ。他のファイルの同期は止めない。
- 既存ファイル（リモートにもあるファイル）への自分の編集は、これまでどおりアップロードする。
- ダウンロードも続ける。
- サイドバーに件数と一覧を出し、行ごとに決めさせる。

clone の後に利用者が新しく作ったファイルは未整理ではないので、通常どおりアップロードされる。未整理の控えはプラグインの `data.json` に持ち、同期のたびに現実と突き合わせて、すでに上がった・消えたパスを落とす。

## Vault 内の設定ファイル

clone が成功した直後に、無いものだけ作る。既存は上書きしない。置き場所はマウントフォルダ直下（＝同期ルート直下）。

| パス | 同期 | 言語 | 中身 |
|---|---|---|---|
| `_Sync/ignore.md` | する | 英語 | 使い方の説明と除外規則 |
| `_Sync/README.md` | する | 英語 | プラグインの説明 |
| `_SyncLocal/ignore.md` | しない | 各自の UI 言語 | 同上（各自用） |

- `_SyncLocal/` は常に同期の対象外。
- `_Sync/ignore.md` は除外できない。除外規則に書かれていても無視して同期する。
- 今後ファイルが増えても、この二つのフォルダの下に置く。

## ignore の書式

`.gitignore` の部分集合。

- `#` で始まる行はコメント。空行は無視。
- `*`（`/` を跨がない）、`?`、`**`（`/` を跨ぐ）。
- 先頭の `/` は同期ルート固定。無ければどの階層でも一致。
- 末尾の `/` はフォルダのみに一致。
- `!` で直前までの規則を打ち消す。
- Markdown ファイルなので、規則をコードブロックに入れても入れなくても読む。

**すでに同期されているファイルが後から除外された場合は、どちらも消さない。** 以後そのパスを対象外として扱い、ベースラインから外すだけにする。除外を解除すると、両側にファイルが残っているので、内容が違えば競合として `.conflict-<UTC>` が作られる。

## 分類の実行

サイドバーの行ごとのボタンで決める。保存される中間状態は「まだ決めていない」だけで、決めた時点で控えから外れる。

- **共有**: 保留を外して同期する。そのファイルは普通の新規ファイルとして上がる。
- **削除**: ローカルのゴミ箱へ送る。リモートには触らない——そもそもリモートに無いファイルだけがここに来る。
- **すべて共有 / すべて削除**: 一覧の全件に同じ判断を当てる。一括削除だけは、件数を出す確認ダイアログを挟む。1 件ずつの削除には出さない。毎回確認を挟むと読まずに押すようになり、肝心の一括削除でも読まれなくなる。

## サイドバー

- 右サイドバーのビュー。リボンとコマンドパレットから開ける。
- 表示するもの:
  - 状態（sync が使えるか。使えないなら理由）。
  - 差分の一覧: アップロード予定 / ダウンロード予定 / 競合 / ローカル固有 / 保留された削除。種別ごとに畳み、既定は閉じておく。数百件を開いたままにすると件数まで辿り着けない。
  - ボタン: 今すぐ同期 / Drive から取り込む / 状態を確認。「状態を確認」は差分を数え直すだけで、同期はしない。ボタンはサイドバーの幅に合わせて折り返す。
  - 各ボタンにツールチップを付け、押す前に何が起きるかを読めるようにする。
  - 同期の一時停止トグル。止まっている間も「今すぐ同期」は押せる。
  - 未整理の各行に「共有」「削除」のボタン。
  - 最終計算時刻。
- 差分を計算し直すのは、次の四つのときだけ。
  1. `ChangeProbe` がリモートの変更を報告したとき（1 リクエストで済む）。
  2. ローカルのファイルイベントが落ち着いたとき（既存の 3 秒デバウンスに相乗り）。
  3. 同期や clone の直後。
  4. 「状態を確認」ボタンを押したとき。

## 出す順

1. **止血**: 要確認状態の検知とアップロード停止、clone、保留削除の承認 UI、最小限のサイドバー（状態・保留削除の一覧・ボタン）。
2. **分類**: `_Sync/` と `_SyncLocal/` の作成、ignore の適用、未整理によるアップロード停止。
3. **仕上げ**: 差分の一覧表示、行ごとの「共有」「削除」、一括操作と確認ダイアログ、同期の一時停止、ツールチップ、`.conflict-*` の整理。

段階 1 だけで、壊れた状態から復旧できるようになる。リリース（tag `0.1.0`）は段階 1 の後に出す。

## 既存の利用者

- ベースラインの形式は変えない。clone は要求しない。
- 要確認の条件に当てはまる Vault だけが止まり、サイドバーから復旧する。
